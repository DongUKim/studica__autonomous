# Studica 로봇 ROS2 패키지 — 처음 보는 사람을 위한 사용 설명서

> **이 설명서는 2026년 전국대회 로봇을 기준으로 만들어졌습니다.**
> 2027년에 로봇을 새로 설계하면(바퀴 배치, 센서 위치, 핀 연결이 바뀌면) **이 패키지의 설정과 계산식도 반드시 같이 고쳐야 합니다.**
> 그대로 쓰면 로봇이 엉뚱한 방향으로 가거나 기록한 길을 따라가지 못합니다. 무엇을 어디서 고쳐야 하는지는 맨 아래 **"9. 2027년에 로봇이 바뀌면 고쳐야 하는 것"**에 정리했습니다.

---

## 1. 이 패키지가 하는 일 (한 줄 요약)

**키보드로 로봇을 운전하고 → 그 길을 녹화하고 → 나중에 로봇이 혼자 그 길을 다시 달리게** 하는 프로그램입니다.

비유하자면 "자동차 운전 연습 → 주행 기록 저장 → 자율주행으로 재생" 입니다.
로봇은 자기 위치를 GPS로 아는 게 아니라 **바퀴가 얼마나 굴렀는지(엔코더)** 와 **얼마나 돌았는지(자이로 센서)** 를 더해서 계산합니다.
그래서 시작 위치를 똑같이 맞춰 주는 게 아주 중요합니다.

## 2. 준비물

| 준비물 | 설명 |
|---|---|
| 로봇 | VMX-pi(작은 컴퓨터) + Titan(모터 드라이버) + 바퀴 3개짜리 옴니휠 로봇 (2026년 로봇) |
| 노트북 | 로봇에 원격 접속(ssh)할 노트북. 같은 와이파이에 있어야 함 |
| 비상정지 버튼 | 로봇의 **EMS 버튼**. 실기 테스트 때는 항상 손 닿는 곳에 |

로봇 안의 컴퓨터에는 ROS2 "Humble" 이 깔려 있습니다. ROS2는 "로봇 프로그램들이 서로 대화하는 규칙" 이라고 생각하면 됩니다.

## 3. 처음 딱 한 번만 하는 설치

로봇 컴퓨터에 접속한 터미널에서 (`ssh -t 사용자이름@로봇IP` 로 접속):

```bash
cd ~/studica_ros2                      # 이 저장소를 받아 둔 폴더로 이동
bash scripts/setup_permissions.sh      # 모터/센서를 건드릴 권한 설정 (한 번만)
source /opt/ros/humble/setup.bash      # ROS2 켜기
colcon build --symlink-install         # 프로그램 빌드 (몇 분 걸림)
```

`colcon build` 가 끝나고 `install` 폴더가 생겼으면 설치 끝입니다.
이후에는 아래 스크립트들이 알아서 ROS2를 켜 주기 때문에 `source` 명령을 매번 칠 필요가 없습니다.

> ⚠️ **접속할 때 `ssh -t` 처럼 `-t` 를 꼭 붙이세요.** 키보드 운전 화면이 `-t` 없이는 안 나옵니다.

## 4. 사용법 ① 키보드로 운전하기

```bash
python3 scripts/teleop.py
```

잠시 기다리면 화면에 운전 상태 창(HUD)이 뜹니다. 그 다음 키보드로 조종합니다.

| 키 | 하는 일 |
|---|---|
| `W` / `S` | 앞으로 / 뒤로 (한 번 누르면 계속 갑니다 — "래칭") |
| `A` / `D` | 왼쪽 / 오른쪽으로 **옆걸음** (옴니휠이라 몸을 안 돌리고 옆으로 갑니다) |
| `Shift+Q` / `Shift+E` | 왼쪽으로 회전 / 오른쪽으로 회전 |
| `스페이스` 또는 `X` | **정지** |
| `1` / `2` / `3` | 속도 느림 / 보통 / 빠름 |
| `+` / `-` | 속도를 10 %씩 올리기 / 내리기 |
| `Z` | 방향 센서(자이로)와 위치 계산을 0으로 리셋 |
| `H` | 도움말 보기 / 닫기 |
| `Ctrl + C` | 프로그램 끄기 (로봇도 같이 멈춤) |

**왜 회전이 소문자 `q` `e` 가 아니고 Shift 를 눌러야 하나요?**
길을 녹화할 때는 "직진·옆걸음"과 "제자리 회전"을 섞지 않는 게 좋습니다. 회전 중에는 거리 센서 값이 흔들려서 나중에 재생할 때 방해가 되기 때문에, 실수로 회전하지 않도록 일부러 Shift 를 붙였습니다.

**로봇이 없을 때 연습하기**

```bash
python3 scripts/teleop.py --sim
```

`--sim` 을 붙이면 진짜 모터 대신 **가짜 로봇(시뮬레이터)** 이 돌아갑니다. 노트북에 ROS2가 있으면 노트북에서도 됩니다.

## 5. 사용법 ② 길 녹화하기 (티칭)

"체크포인트"란 로봇이 들르는 지점 이름입니다. 예: `ST`(출발지), `P1`, `P2`(배송지) …
녹화는 **체크포인트 → 체크포인트 한 구간씩** 합니다. 이 한 구간을 **"레그(leg)"** 라고 부릅니다.

```bash
python3 scripts/teach.py mission_a
```

`mission_a` 는 녹화 묶음 이름입니다(폴더 이름이 됩니다). 연습장/대회장 별로 다르게 지어도 됩니다.

운전 키는 위와 똑같고, 녹화용 키가 추가됩니다:

| 키 | 하는 일 |
|---|---|
| `[` | **녹화 시작.** 출발 체크포인트 이름 → 도착 체크포인트 이름을 물어봅니다 (예: `ST` 엔터, `P1` 엔터) |
| `]` | **녹화 끝 + 저장** |
| `ESC` | 이번 녹화 버리기 (정말 버릴지 `y` 로 확인) |
| `R` | 방금 그 구간을 다시 녹화 (이름 다시 안 물어봄) |

### 녹화할 때 꼭 지킬 것 (화면에도 계속 나옵니다)

1. **멈춘 상태에서 `[` 를 누르고, 멈춘 상태에서 `]` 를 누르세요.** 움직이는 중엔 시작이 안 됩니다.
2. **끝난 자리가 다음 레그의 시작 자리입니다.** `ST→P1` 을 끝낸 자리에서 그대로 `P1→P2` 를 시작하세요.
3. **회전은 꼭 필요할 때만.** 가능하면 `A`/`D` 옆걸음으로 해결하세요.
4. **벽 옆을 지날 때는 벽에서 15~25 cm 떨어져서** 가세요. 그래야 거리 센서가 벽을 "기억"해서, 재생할 때 로봇이 조금 밀려도 스스로 바로잡습니다. (센서는 30 cm 안쪽만 기억합니다.)
5. **녹화한 속도가 재생 때 최고 속도가 됩니다.** 너무 느리게 녹화하면 재생도 느립니다. 마지막 녹화는 실제 경기 속도의 80 % 정도로.

저장된 파일은 로봇 컴퓨터의 `~/studica_missions/mission_a/taught_legs/` 폴더에 들어갑니다.
같은 구간을 다시 녹화하면 예전 것은 `.v1`, `.v2` 이름으로 3개까지 남겨 둡니다.

## 6. 사용법 ③ 녹화한 길 자동으로 달리기 (재생)

```bash
python3 scripts/repeat.py mission_a --list       # 녹화된 구간 목록 보기
python3 scripts/repeat.py mission_a ST P1 P2     # ST → P1 → P2 순서로 달리기
```

**시작 전에 로봇을 첫 체크포인트(위 예시에서는 `ST`)의 녹화 시작 위치·방향에 정확히 놓으세요.**
로봇은 "지금 있는 자리 = 녹화 시작 자리" 라고 믿고 출발합니다. 2 mm, 0.5° 만 틀어져도 끝에서는 몇 cm 씩 벌어집니다. 그래서 출발 자리에 **거치 틀(지그)** 을 만들어 두는 것을 강력히 권합니다.

- 녹화 안 한 구간을 시키면 출발하지 않고 `untaught edge ST->P3` 처럼 알려줍니다.
- 달리다가 길에서 8 cm 넘게 벗어난 상태가 0.5초 이상 이어지면 **스스로 멈추고 실패** 라고 알립니다.
- `--speed 0.8` 을 붙이면 녹화 속도의 80 % 로 달립니다. (1.0 이 최대)
- `Ctrl + C` 로 언제든 멈춥니다.

### 재생이 잘 되는지 한 번에 점검하기

```bash
python3 scripts/repeat.py mission_a --validate
```

녹화된 모든 구간을 순서대로 달린 뒤 성적표(`report.txt`)를 만듭니다. `~/studica_missions/mission_a/validation/` 에 저장됩니다.
"옆으로 벗어난 거리 95 %가 2.5 cm 이내, 도착 오차 1.5 cm 이내" 면 합격입니다.

- 특정 구간만 나쁘면 → 그 구간만 다시 녹화
- 전부 같은 방향으로 틀어지면 → 출발 지그나 자이로 센서 점검
- 갑자기 센서 값이 다 안 맞으면 → 코트(벽·장애물)가 바뀐 것. 다시 녹화

## 7. 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 스크립트가 "워크스페이스가 빌드되지 않았습니다" | 3번 설치의 `colcon build` 를 안 했거나 실패함 |
| 모터가 전혀 안 돌고 로그에 `EMS engaged` 가 계속 뜸 | 비상정지 버튼이 눌려 있거나, 버튼 연결 설정(`ems_pressed_value`)이 반대. `src/studica_base/README.md` 참고 |
| 화면(HUD)이 안 나오고 글자만 흘러감 | `ssh -t` 로 다시 접속 |
| `W` 를 눌렀는데 뒤로/옆으로 감 | 모터 방향 설정이 반대. 9번의 "바퀴 방향" 항목 |
| 재생 때 점점 한쪽으로 쏠림 | 바퀴 크기·중심 거리 값이 실제와 다름. 9번의 "바퀴 크기·거리" 항목 |

자세한 로그는 `~/studica_logs/` 폴더에 실행할 때마다 파일로 남습니다. 선생님이나 선배에게 보여 줄 때 이 파일을 같이 보여 주세요.

## 9. ⚠️ 2027년에 로봇이 바뀌면 고쳐야 하는 것 (매우 중요)

이 프로그램은 **2026년 로봇의 모양과 배선을 핀번호로 안내하고 있습니다.**
로봇을 새로 만들면 아래를 **하나씩 확인해서 고쳐야** 합니다. 하나라도 빠지면 로봇이 이상하게 움직입니다.
고친 뒤에는 반드시 `colcon build` 를 다시 하고, `--sim` 과 실기 텔레옵으로 확인하세요.

| 바뀐 것 | 고칠 파일 | 무엇을 |
|---|---|---|
| **핀 연결** (모터 번호, 초음파·PSD·LED 핀) | `src/studica_base/config/params.yaml` | 각 센서 블록의 `ping`/`echo`/`port`/`pin`. PSD(적외선) 는 아날로그 번호에 22를 더한 값(0→22, 1→23…)을 씁니다. 바꾼 내용을 `pin_setting.md` 에도 적어 두세요 |
| **바퀴 방향** (앞으로 가라는데 뒤로 감) | 같은 파일 `titan0` → `m_0`~`m_2` | `invert_motor: true/false`. 위치 계산이 반대로 되면 `invert_encoder` 도 |
| **바퀴 크기, 엔코더** (바퀴 지름·기어비가 바뀜) | 같은 파일 `dist_per_tick` | 바퀴 한 바퀴 둘레 ÷ 엔코더 한 바퀴 펄스 수. 1 m 를 직접 재서 맞춥니다 |
| **바퀴 사이 거리** (로봇 중심에서 바퀴까지) | `src/studica_base/config/params.yaml` 의 `wheel_base_r_m` (기본 0.120 m) | 제자리 360° 돌려서 화면의 각도와 맞을 때까지 조정 |
| **바퀴 개수·배치가 바뀜** (예: 3개→4개 메카넘) | `src/studica_base/studica_base/omni_kinematics.py` 그리고 `src/studica_repeat/studica_repeat/sim_model.py` | 속도를 바퀴 회전으로 바꾸는 **계산식 자체**를 새 로봇에 맞게 다시 써야 합니다. 두 파일이 같은 식을 갖고 있으니 **둘 다** 고치세요. 테스트(`src/studica_base/test`)도 같이 |
| **모터 힘·속도 특성** (다른 모터, 무거워진 로봇) | `src/studica_base/config/params.yaml` 의 `k_s`, `k_v`, `k_p` | 속도 명령과 실제 속도가 다르면 조정. 절차는 `src/studica_base/README.md` |
| **거리 센서 위치** (왼쪽/오른쪽/앞 센서가 어디 붙었나) | `src/studica_repeat/studica_repeat/core/leg_io.py` 의 `LEFT_CHANNELS` `RIGHT_CHANNELS` `FRONT_CHANNELS` | 재생 중 "벽과의 거리로 위치 바로잡기"가 **어느 센서가 어느 쪽을 보는지**를 전제로 합니다. 센서를 옮기면 이 목록과 시뮬레이터 센서 위치(`sim_node.py` 의 `sensor.*` 값)를 고치세요 |
| **센서 종류** (PSD 가 30 cm 이상도 정확하게 되거나, 초음파 범위가 바뀜) | 같은 파일 `PSD_MAX_M`, `US_MAX_M` | 기억해도 되는 최대 거리 |
| **원하는 운전 속도** | `src/studica_teleop/studica_teleop/teleop_state.py` 의 `LIN_PRESETS`, `ANG_PRESETS` | 1/2/3 키 속도 |
| **재생이 너무 흔들리거나 느리게 따라감** | `src/studica_repeat/config/repeat_params.yaml` | 길 따라가는 세기(`k_lat`, `k_th`), 최대 속도(`vmax`), 벗어남 허용(`dev_lat`) |
| **코트(경기장) 가 바뀜** | 프로그램 수정 없음 | **모든 구간을 다시 녹화** 하면 됩니다 (구간당 2~3분) |

**절대 잊지 말 것**

- 이 프로그램의 "재생"은 마법이 아닙니다. **바퀴 회전 수와 자이로로 위치를 추측**하고, **벽 옆에서만** 거리 센서로 바로잡습니다. 새 로봇에서 바퀴 계산식이 틀리면 위치 추측부터 틀어져서 재생 전체가 안 됩니다.
- 그래서 새 로봇에서는 **순서를 지켜서** 확인하세요:
  1. 텔레옵으로 `W`/`A`/`Shift+Q` 가 바른 방향으로 가는가
  2. 1 m 직진했을 때 화면 위치가 1.00 m 근처인가
  3. 제자리 한 바퀴 돌았을 때 각도가 360° 근처인가
  4. 그 다음에야 녹화·재생
- 위 4단계를 통과하기 전에 재생을 시도하면 "왜 안 되는지" 원인을 찾을 수 없습니다.
